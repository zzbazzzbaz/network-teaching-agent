## 1.1 一个包从你的电脑到目标，中间发生了什么

先看一条最简单的路径：

```text
你的电脑  ────  R1  ────  R2  ────  R3  ────  目标服务器
   ^            ^         ^         ^              ^
 端主机       路由器     路由器     路由器         端主机
```

- **端主机**：真正在说话的两台机器，比如你的电脑、网站服务器。
- **路由器**：不关心你的内容，只负责把包往目标方向转发。
- **跳（hop）**：数据包从一台机器到下一台机器，算一跳。上图中，你的电脑到目标是 4 跳。平时说“第 N 跳”，指的是 TTL=N 时回包的那台路由器；“最后一跳”指的是路径末端（目标）。

互联网不是“一台大机器”，而是很多张网络互相连起来，所以也叫 **network of networks**。每张网络有自己的运营者，路由器负责把包从一张网络送到另一张网络。

这里有一个很重要的前提：**互联网只提供 best-effort（尽力而为）服务。**

意思是：

- 包可能丢；
- 包可能重复；
- 包可能乱序；
- 包可能损坏；
- 网络会尽量送，但不保证。

这不是“网络坏了”，而是互联网的设计选择。记住这一点，后面看到 `*`、重复的路由器、偶尔收不到回包，就不会觉得奇怪。

## 1.2 头部与负载：为什么每个包都要“套信封”

假设你只把一段文字发给路由器，路由器不知道：

- 这段文字要送到哪？
- 是谁发的？
- 里面装的是 UDP 还是 ICMP？
- 这个包还能走几跳？

所以每个包都要在数据前面加一段“说明”，叫 **头部（header）**；真正的数据叫 **负载（payload）**。

```text
+----------------------+
| IPv4 头部             |  源 IP、目标 IP、TTL、协议号……
+----------------------+
| UDP 头部              |  源端口、目标端口……
+----------------------+
| 负载                  |  你真正发送的内容
+----------------------+
```

可以把它想成寄快递：

- 信封上写收件人地址 → IPv4 头部的目标 IP；
- 信封上写寄件人地址 → IPv4 头部的源 IP；
- 信封上写“易碎品” → 协议号、端口等信息；
- 信纸本身 → 负载。

### 协议号与端口

IPv4 头部里有一个 **Protocol（协议号）** 字段，用来告诉接收方“IP 负载应该交给谁”：

| 协议号 | 上层协议 |
|---|---|
| 1 | ICMP |
| 17 | UDP |

UDP 头部里有两个 **端口号**：

| 字段 | 作用 |
|---|---|
| 源端口 | 发送方应用的“门牌号” |
| 目标端口 | 接收方应用的“门牌号” |

端口解决的是“同一台机器上有很多程序，这个包该给谁”的问题。IP 地址负责把包送到机器，端口负责把包送到机器上的某个程序。

> 注意：这里说的是**逻辑端口**（软件里的编号），不是网线插口那种物理端口。

## 1.3 TTL：给包一个“跳数预算”

路由器有时候会配错路由，导致一个包在两台路由器之间来回转发：

```text
你的电脑 → R1 → R2 → R3 → R4 → R3 → R4 → R3 → ...
```

如果没有限制，这个包会永远转下去，浪费带宽。为了解决这个问题，IPv4 头部里有一个 **TTL（Time To Live）** 字段。

TTL 的工作方式：

1. 发送方给包设一个初始 TTL，比如 64；
2. 每经过一个路由器，路由器把 TTL 减 1；
3. 如果减完变成 0，路由器就**丢弃**这个包；
4. 同时，路由器给发送方回一个 **ICMP Time Exceeded** 错误包，告诉发送方“你的包在我这里过期了”。

注意：**TTL 现在表示“还能走几跳”，不是“还能活几秒”。** 名字是历史遗留的，早期确实按时间算，后来改成了跳数。

| 你发出的 TTL | 经过 R1 后 | 经过 R2 后 | 结果 |
|---|---|---|---|
| 1 | 0 | — | R1 丢弃，回 Time Exceeded |
| 2 | 1 | 0 | R2 丢弃，回 Time Exceeded |
| 3 | 2 | 1 | R3 丢弃，回 Time Exceeded |
| 64 | 63 | 62 | 继续往目标走 |

## 1.4 traceroute 的核心把戏

现在问题来了：我们怎么知道中间的路由器是谁？

关键观察是：**TTL 过期时，路由器会回一个 ICMP 错误包，而这个错误包的源 IP 就是路由器自己。**

于是 traceroute 这样做：

```text
第 1 次：发一个 TTL=1 的包，目标是最终目标
          → R1 把 TTL 减到 0，丢弃，回 ICMP
          → 我们收到 R1 的 ICMP，知道第 1 跳是 R1

第 2 次：发一个 TTL=2 的包，目标还是最终目标
          → R1 转发，R2 把 TTL 减到 0，丢弃，回 ICMP
          → 我们收到 R2 的 ICMP，知道第 2 跳是 R2

第 3 次：TTL=3
          → 收到 R3 的 ICMP，知道第 3 跳是 R3
```

这里有一个很容易误解的点：

> **我们发的包，目标地址始终是最终目标，不是中间的路由器。**

我们并不知道中间路由器是谁，也不可能直接“问”它们。我们只是利用 TTL 让包在指定位置过期，然后从错误包的源 IP 里“读”出路由器的地址。

> 真实沙箱里，TTL=1/2 可能完全没有回包；第一次看到路由器可能是 TTL=3 或 TTL=5。原理不变，只是前面的路由器选择不回复 ICMP。不要因为 TTL=1 是 `*` 就以为代码错了。

用时序图表示 TTL=1：

```text
你的电脑                         R1                         目标
   |                             |                           |
   |--- UDP, TTL=1, dst=目标 --->|                           |
   |                             | TTL 减到 0，丢弃           |
   |<-- ICMP Time Exceeded ------|                           |
   |    src=R1                   |                           |
```

TTL=2：

```text
你的电脑                R1                 R2                目标
   |                    |                  |                  |
   |--- UDP, TTL=2 ---->|                  |                  |
   |                    |--- TTL=1 ------->|                  |
   |                    |                  | TTL 减到 0，丢弃  |
   |<------------- ICMP Time Exceeded -----|                  |
   |                    src=R2             |                  |
```

## 1.5 三种结果

一次探测，可能收到三种结果：

### 1. Time Exceeded（TTL 过期）

- ICMP `type = 11`, `code = 0`
- 由**中间路由器**发出
- 含义：你的包在我这里过期了，我是第 N 跳
- 这是 traceroute 最常收到、也是最想要的结果

### 2. Port Unreachable（端口不可达）

- ICMP `type = 3`, `code = 3`
- 由**目标主机**发出（理想模型；NAT/防火墙也可能发 `3/3`）
- 含义：包已经到达目标，但目标上没有程序监听你发的那个 UDP 端口
- 这是 traceroute 判断“到了”的信号

为什么目标会回这个？因为我们故意把 UDP 包发到一个**没人监听的端口**（比如 33434）。在本实验的理想模型里，目标主机的内核收到后会说：“这个端口没人要”，于是回一个 Port Unreachable。

### 3. 沉默（`*`）

- 没有收到任何回包
- 可能原因：
  - 路由器配置为不回复 ICMP；
  - 包在网络上丢了；
  - 目标或防火墙不回复；
  - 你等的时间不够。

在 traceroute 的输出里，沉默通常显示为 `*`。**这是正常现象**，真实互联网上很多路由器就是不理你。

| 结果 | ICMP type/code | 谁发的 | 说明 |
|---|---|---|---|
| Time Exceeded | 11 / 0 | 中间路由器 | 第 N 跳找到了 |
| Port Unreachable | 3 / 3 | 目标主机（理想模型） | 到了，可以停 |
| 沉默 | — | — | 这一跳没回，显示 `*` |

## 1.6 你要写的函数

打开 `/root/workspace/traceroute.py`，你会看到这个骨架：

```python
def traceroute(sendsock: util.Socket, recvsock: util.Socket, ip: str) \
        -> list[list[str]]:
    """ ... """
    for ttl in range(1, TRACEROUTE_MAX_TTL+1):
        util.print_result([], ttl)
    return []
```

现在它只会对每个 TTL 打印 `*`。你要把它改成真正去探测。

函数的接口约定（契约，很重要，自检会看）：

> 本沙箱没有自动评测；这里的“验收”是自检清单。如果课程另有评分系统，以课程要求为准。

| 项目 | 要求 |
|---|---|
| 参数 `sendsock` | 用来发 UDP 探测包的 socket |
| 参数 `recvsock` | 用来收 ICMP 回包的 socket |
| 参数 `ip` | 目标主机的 IP 地址（字符串） |
| 返回值 | `list[list[str]]`，第 i 个子列表对应 TTL=i+1 |
| 子列表内容 | 除路径末端外，该 TTL 发现的所有路由器 IP；可以为空。若本跳发现目标，按本实验要求只保留 `[ip]` |
| 顺序 | 子列表内顺序任意 |
| 打印 | 每个 TTL 调一次 `util.print_result(routers, ttl)` |
| 终点 | 如果发现了 `ip`，路径末端的子列表只保留 `[ip]`（本实验要求） |

例子（只表示结构，`R1`/`R2`/`目标` 代表具体 IP）：

假设 TTL=1 没有回包，TTL=2 发现两台路由器，TTL=3 到达目标，那么返回值形如：

```python
[[], ["R1", "R2"], ["目标"]]
```

对应的打印输出类似：

```text
 1: *
 2: R1
    R2
 3: 目标
```

> `util.print_result` 会帮你做反向域名解析，所以真实输出可能是 `hostname (IP)` 的形式。解析不到就只显示 IP。

## 1.10 常见误区

| 误区 | 纠正 |
|---|---|
| “TTL 是生存时间，单位是秒” | 现在表示还能走几跳；名字是历史遗留 |
| “traceroute 直接问路由器‘你是谁’” | 不是；它让包在指定跳数过期，从 ICMP 错误包里读源 IP |
| “某一跳是 `*`，后面就看不见了” | 不一定；那台路由器可能只是不回复，但仍然会转发 |
| “到了目标就一定会回 Port Unreachable” | 不一定；防火墙/配置可能不回复，这时会跑到 30 跳 |
| “`*` 说明代码错了” | 真实网络里很常见；先确认系统 traceroute 是否也这样 |
| “返回值里每一跳只能有一个 IP” | 同一 TTL 可能有多个路由器，子列表可以有多个 IP |
