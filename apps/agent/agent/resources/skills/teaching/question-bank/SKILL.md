# 题库使用

题库是结构化事实数据，不写进 `/memory`。本 skill 负责“怎么查、怎么录、怎么展示”，不重复工具参数定义。

## 1. 题库边界

- 公共题：管理员/教师预置的课程参考语料，`owner_id` 为空；
- 我的题库：当前学生自己的私有题，只有本人可见；
- 公共题不能加入我的题库，也不能直接产生作答；
- 学生要练公共题时，基于题干生成一道新的私有题，用 `ask_student` 出题；
- 不读取其他学生的私有题，不发布公共题，不编造题号、年份或来源。

## 2. 知识点

题库使用教材 `00-toc.md` 的目录编号，不使用自由标签。

- 章、节、子节都是合法节点；
- `99` 是跨章节综合节点；
- 每道题必须有一个主知识点，`secondary_knowledge_point_ids` 最多 3 个；
- 主/辅不能重复，辅知识点不能包含主知识点；
- 不确定时用相关小节的 LCA 或父节点，不要编造编号；
- 知识点只用于检索/展示，不做掌握状态、薄弱点、准确率或错题本。

例子：

| 题目 | 主 | 辅 |
|---|---|---|
| TCP 慢开始 cwnd 怎么变 | `5.8.2` | 无 |
| 慢开始和拥塞避免的区别 | `5.8.2` | 无 |
| 拥塞控制一般原理 + 慢开始 | `5.8` | `5.8.1`, `5.8.2` |
| DNS + TCP + IP 综合 | `99` | `6.1.1`, `5.9.1`, `4.2.2` |

## 3. 检索

`search_questions` 默认 `scope=all`，同时搜公共题和我的题库：

- `scope=public`：只查公共参考题；
- `scope=mine`：只查学生自己的题；
- `knowledge_point_id` 精确匹配主/辅知识点；
- `knowledge_point_prefix` 按章节/小节过滤，如 `5`、`5.8`；
- 默认 `limit=10`，最大 20；
- `detail=summary` 不返回答案；`detail=full` 最多 3 条，含答案/参考答案，只用于 agent 讲解；
- `last_attempt_at` 只对私有题有意义，表示最近一次作答时间；
- 不推断掌握度、薄弱点、正确率，也不返回作答次数或备注；
- `note` 字段只是预留，v1 `ask_student` 不采集；不要向学生承诺“已记录备注”。

检索结果只用于选择题目或讲解。一次最多向学生展示 3 道题，不要把题库全文贴出，不要展示内部 `question_id`。

## 4. 出题与录题

- 检查题/引导题：用 `ask_student`，必须标注知识点；学生作答后自动保存题目和答案；
- 学生明确说“把这道题记下来/加入题库”：用 `save_question`，只创建私有题；
- 学生没有明确要求时，不要主动录题；
- 不做去重；同一道题重复保存会产生多条；
- 学生要求发布公共题时，说明当前不支持，建议保存私有题；
- `save_question` 的单选必须提供 `correct_option`；简答可用 `reference_answer` 给出参考答案。

## 5. 答案与反馈

- 题目答案、`correct_option`、`reference_answer` 不能提前展示；
- `ask_student` 返回学生答案和参考答案后，由 agent 自己判断，工具不判分；
- 单选答对：先确认，再追问“为什么”或换一个条件；
- 单选答错：先问学生怎么排除其他选项，再给提示；
- 简答不结构化判分，按关键点对照参考答案反馈，不要求逐字一致；
- 不把参考答案直接当作完整讲解；先指出学生答对和缺失的关键点。

## 6. 与记忆的关系

- 题库内容、题干全文、选项、答案、解析、作答明细都不写 `/memory`；
- 记忆只记录概念状态、误解、下一步和“上次同步日期”；
- 需要历史题目或作答时，用 `search_questions(scope='mine')` 查；
- 不把题库统计写进 memory，也不根据几次作答推断掌握度。

## 7. 调用前检查

- [ ] 知识点使用教材目录编号了吗？
- [ ] 主知识点只有一个，辅知识点不超过 3 个且不重复吗？
- [ ] 只查到了当前学生有权访问的题吗？
- [ ] summary/full 的使用场景正确吗？
- [ ] 没有把答案提前展示给学生吗？
- [ ] 学生明确要求录题时才调用 `save_question` 吗？
- [ ] 没有把题库内容复制进 memory 吗？
