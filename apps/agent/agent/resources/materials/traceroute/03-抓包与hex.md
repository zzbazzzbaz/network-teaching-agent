# 第 3 章 抓包与 hex：把回包变成可读的字节

现在你手里有一段回包字节。这一章教你把它们拆成可读的字段。

## 本章目标

学完这一章，你应该能：

1. 把 `recvfrom()` 拿到的 `bytes` 打印成十六进制；
2. 说出一个 ICMP 错误包的四个部分：外层 IPv4、ICMP、内层 IPv4、内层 UDP；
3. 在 hex 里找到每一层的起始偏移；
4. 从 hex 里读出“谁发的”“原始探测发给谁”“是哪个探测”；
5. 不被 `len(buf)`、`total length`、NAT、IP options 这些细节绊住。

这一章不要求写解析代码，只要求“眼睛能看懂”。

> 本章所有 hex 都来自 2026-10-26 的真实沙箱抓包：沙箱地址 `169.254.68.6/30`，默认网关 `169.254.68.5`，目标 `8.8.8.8`。每次运行的 IP ID、校验和、内层 UDP 源端口可能不同，但字段含义不变。

---

## 3.1 为什么是十六进制

计算机里最常用的基本单位是字节（byte），1 字节 = 8 位（bit）；比字节更小的是位。直接打印 `bytes`，Python 会显示成 `b'E\x00\x00@...'`，很难读。

十六进制（hex）把 1 字节写成 2 个字符：

| 字节值 | 二进制 | 十六进制 |
|---|---|---|
| 0 | 0000 0000 | `00` |
| 64 | 0100 0000 | `40` |
| 255 | 1111 1111 | `ff` |

所以：

```python
b"\x45\xb8\x00\x38".hex()   # '45b80038'
```

`0x45` 是 69，`0x38` 是 56。看到 `45 b8 00 38`，你就知道这是 4 个字节，也是真实包 A 的开头。

### 偏移

我们说的“偏移 0”“偏移 20”，是指从缓冲区第几个字节开始数，**从 0 开始**。

```text
偏移:  0   1   2   3   4   5  ...
字节: 45  b8  00  38  fc  80 ...
```

### 大端序

网络协议统一使用**大端序（big-endian，网络字节序）**：高位字节在前。

比如 `00 38` 按大端序读是 `0x0038 = 56`；如果按小端序读，就是 `0x3800 = 14336`。

本实验按大端序解析。真实网络里偶尔有路由器把 `total length` 写成小端序；那是路由器的怪行为，本实验不处理，遇到字段值明显不对的包可以先忽略。

---

## 3.2 一个回包的四层结构

当 TTL 过期时，路由器回给你的不是“一个简单的错误消息”，而是一个套娃：

```text
┌─────────────────────────────────────────────┐
│ 外层 IPv4 头（20 字节起）                    │  ← 谁发的？路由器
├─────────────────────────────────────────────┤
│ ICMP 头（8 字节）                            │  ← 出了什么错？
├─────────────────────────────────────────────┤
│ 内层 IPv4 头（20 字节起）                    │  ← 原始探测包的 IP 头
├─────────────────────────────────────────────┤
│ 内层 UDP 头（8 字节）                        │  ← 原始探测包的 UDP 头
├─────────────────────────────────────────────┤
│ 原始负载（可能只带前 8 字节，也可能多带）    │
└─────────────────────────────────────────────┘
```

为什么要有内层？

ICMP 错误包的规则是：**把触发错误的原始 IP 头，加上原始数据至少前 8 字节，一起放进负载里。** 这样发送方才知道“是哪一个包出错了”。

这 8 字节正好覆盖 UDP 头：源端口、目标端口、长度、校验和。不过很多实现会多带一些原始数据，也有一些只带 8 字节；下面你会看到真实沙箱里两种都出现了。

> 这是 traceroute 能匹配“哪个回包对应哪个探测”的关键。第 7、8 章会用到。

## 3.3 在代码里拿到 hex

在第 2 章的 `probe_once.py` 里，拿到 `buf` 后，把打印部分改成：

```python
if recvsock.recv_select():
    buf, addr = recvsock.recvfrom()
    print("from:", addr)
    print("len:", len(buf))
    print(buf.hex())
```

`buf.hex()` 会把整个包打印成一长串 hex。想分行看，可以加一个小工具：

```python
def dump(buf: bytes):
    for i in range(0, len(buf), 16):
        chunk = buf[i:i + 16]
        text = "".join(chr(b) if 32 <= b < 127 else "." for b in chunk)
        print(f"{i:04x}  {chunk.hex(' '):<48}  {text}")
```

真实输出类似：

```text
0000  45 b8 00 38 fc 80 40 00 f9 01 5e 53 65 e2 d2 51  E..8..@...^Se..Q
0010  a9 fe 44 06 0b 00 73 5d 00 00 00 00 45 00 00 21  ..D...s]....E..!
0020  fc 80 40 00 01 11 ac 30 c0 a8 00 63 08 08 08 08  ..@....0...c....
0030  e5 b9 82 9b 00 0d 99 73                          .......s
```

这个 `dump` 函数只是让你“看见”字节，不参与最终实现。可以放在 `probe_once.py` 里，不要放进 `traceroute.py`。

## 3.4 可选：用 `tcpdump` / `xxd` 对照

沙箱里装了 `tcpdump` 和 `xxd`。它们可以用来对照，但不是主线。

### `tcpdump`

沙箱的出网接口是 `eth0`，用：

```bash
tcpdump -ni eth0 -X icmp
```

再运行 `probe_once.py`。你会看到 ICMP 回包的 hex。

注意：

- `-i eth0` 是以太网头，通常 14 字节；
- `-i any` 在 Linux 上通常是 SLL/SLL2 伪头，长度常见 16 字节；
- 而 `recvfrom()` 的 `buf` 从 IPv4 头开始，不含链路层头。

对照时以 `buf` 的 IPv4 起点为准，不要死记 14 或 16 字节。

### `xxd`

把 hex 字符串还原成字节并分行：

```bash
echo "45b80038fc804000f9015e5365e2d251" | xxd -r -p | xxd -g 1
```

`-r -p` 表示“把纯 hex 还原成二进制”，`-g 1` 表示每字节一组。上面只还原了前 16 字节；看完整包用 `buf.hex()` 或把整段 hex 粘进去。

## 3.5 逐字节标注一个真实 Time Exceeded 包（包 A）

下面这个包是 2026-10-26 沙箱里的另一次真实抓包（TTL=6；不必和你在第 2 章抓到的完全一样）：

- 你的沙箱：`169.254.68.6`
- TTL=6 的可见路由器：`101.226.210.81`
- 目标：`8.8.8.8`
- 原始探测：源端口 58809（内核分配），目标端口 33435，负载 `hello`
- 外层 IPv4 TTL：249（回包在路上走了几跳）
- 内层 IPv4 TTL：1（原始探测到达路由器时只剩 1）

完整 hex（56 字节）：

```text
45b80038fc804000f9015e5365e2d251
a9fe44060b00735d0000000045000021
fc8040000111ac30c0a8006308080808
e5b9829b000d9973
```

分行看：

```text
偏移   字节
0000   45 b8 00 38 fc 80 40 00 f9 01 5e 53 65 e2 d2 51
0010   a9 fe 44 06 0b 00 73 5d 00 00 00 00 45 00 00 21
0020   fc 80 40 00 01 11 ac 30 c0 a8 00 63 08 08 08 08
0030   e5 b9 82 9b 00 0d 99 73
```

### 四层边界

| 层 | 起始偏移 | 长度 | 结束偏移 |
|---|---|---|---|
| 外层 IPv4 头 | 0 | 20 | 19 |
| ICMP 头 | 20 | 8 | 27 |
| 内层 IPv4 头 | 28 | 20 | 47 |
| 内层 UDP 头 | 48 | 8 | 55 |
| 原始负载 | 56 | 0（未包含） | — |

> 这里是“没有 IP options”的情况。如果 `IHL > 5`，外层/内层 IP 头会更长，后面的偏移要相应后移。第 5 章会把这个头长字段命名为 `header_len`，并用它动态算偏移。

### 逐字段读

**外层 IPv4（偏移 0–19）**

| 字段 | 字节 | 值 | 含义 |
|---|---|---|---|
| Version + IHL | 0 | `45` | 版本 4，IHL=5 → 头长 5×4=20 字节 |
| TOS | 1 | `b8` | DSCP/ECN，真实网络里可能非 0；本实验忽略 |
| Total Length | 2–3 | `00 38` | 56 字节 |
| Identification | 4–5 | `fc 80` | 64640；分片用，本实验忽略 |
| Flags + Frag Offset | 6–7 | `40 00` | Flags=0x2（DF），Frag Offset=0 |
| TTL | 8 | `f9` | 249 |
| Protocol | 9 | `01` | 1 = ICMP |
| Checksum | 10–11 | `5e 53` | 0x5e53；本实验不校验 |
| Source | 12–15 | `65 e2 d2 51` | 101.226.210.81（路由器） |
| Destination | 16–19 | `a9 fe 44 06` | 169.254.68.6（你的沙箱） |

**ICMP（偏移 20–27）**

| 字段 | 字节 | 值 | 含义 |
|---|---|---|---|
| Type | 20 | `0b` | 11 = Time Exceeded |
| Code | 21 | `00` | 0 = TTL expired |
| Checksum | 22–23 | `73 5d` | 0x735d；本实验不校验 |
| Rest | 24–27 | `00 00 00 00` | 本实验为 0 |

**内层 IPv4（偏移 28–47）**

| 字段 | 字节 | 值 | 含义 |
|---|---|---|---|
| Version + IHL | 28 | `45` | IPv4，20 字节头 |
| TOS | 29 | `00` | 0 |
| Total Length | 30–31 | `00 21` | 33 字节（原始探测包的总长） |
| Identification | 32–33 | `fc 80` | 64640；和你的探测包一致 |
| Flags + Frag Offset | 34–35 | `40 00` | Flags=0x2（DF） |
| TTL | 36 | `01` | 原始探测到达这里时只剩 1 跳 |
| Protocol | 37 | `11` | 17 = UDP |
| Checksum | 38–39 | `ac 30` | 0xac30 |
| Source | 40–43 | `c0 a8 00 63` | 192.168.0.99（**不是**你的沙箱 IP，见下） |
| Destination | 44–47 | `08 08 08 08` | 8.8.8.8（目标） |

**内层 UDP（偏移 48–55）**

| 字段 | 字节 | 值 | 含义 |
|---|---|---|---|
| Source Port | 48–49 | `e5 b9` | 58809（内核分配的源端口） |
| Destination Port | 50–51 | `82 9b` | 33435（你发的目标端口） |
| Length | 52–53 | `00 0d` | 13（8 UDP + 5 负载） |
| Checksum | 54–55 | `99 73` | 0x9973 |

**负载**

这个包**没有**包含 `hello` 这 5 个字节。内层 IPv4 的 `Total Length` 是 33（20 IP + 8 UDP + 5 负载），但 ICMP 实际只带了 20 + 8 = 28 字节。这是完全正常的：ICMP 错误包只要求带原始数据的**至少前 8 字节**，多带少带由路由器决定。

### 另一跳的真实反例：带 payload 的版本

另一跳（TTL=14）的路由器 `203.22.178.22` 返回了 61 字节，带了 `hello`：

```text
45b8003da27d0000f901b258cb16b216
a9fe44060b00061b0000000045200021
8b4b400001111d46c0a8006308080808
99f8829a000de53568656c6c6f
```

- 外层 Total Length = 61 = 20 + 8 + 20 + 8 + 5；
- 内层 Total Length = 33；
- 内层 UDP Length = 13；
- 最后 5 字节 `68 65 6c 6c 6f` = `hello`。

所以真实网络里，**不同路由器、不同 TTL 的返回字节数可能不同**。解析时不要假设固定长度。

### 为什么内层源 IP 是 192.168.0.99？

沙箱出网经过 NAT。NAT 会改写 ICMP 错误包里的**内层源地址**，所以你看到的 `192.168.0.99` 不是你的沙箱 `169.254.68.6`，而是 NAT 内部的地址。

这带来一个非常重要的实践结论：

> **不要用内层源 IP 判断“这是不是我的探测”。**  
> 用**内层目的 IP**（`8.8.8.8`）和**内层 UDP 目的端口**（`33435`）来判断。

## 3.6 从 hex 读三个事实

拿到一个 ICMP 错误包，先别急着看所有字段。先回答三个问题：

### 事实 1：谁发的？

看**外层 IPv4 的 Source**（偏移 12–15）。

在上面的例子里是 `101.226.210.81`——一台真实路由器。它告诉你“这个错误是我产生的”。

### 事实 2：原始探测发给谁？

看**内层 IPv4 的 Destination**（偏移 44–47，前提是无 options 的 20 字节头）。

在上面的例子里是 `8.8.8.8`——你的目标。

### 事实 3：是哪个探测？

看**内层 UDP 的 Destination Port**（偏移 50–51，前提是无 options）。

在上面的例子里是 `33435`。如果你每个探测包用不同的目标端口，就能靠这个字段区分。

> 注意：不要看内层 Source（偏移 40–43）。真实沙箱里它是 `192.168.0.99`，被 NAT 改写过。

## 3.7 再看两个真实包

下面两个包也来自同一个沙箱。先自己判断：哪个表示“到了”，哪个应该被忽略？

### 包 B：Port Unreachable

```text
45b8003800000000fa01c1f808080808
a9fe44060303e8230000000045000021
8f374000011118fac0a8006308080808
99f8829a000de535
```

### 包 C：Echo Reply

这是同时运行 `ping 8.8.8.8` 抓到的真实 Echo Reply：

```text
45b8005400000000fa01c1dc08080808
a9fe4406000090b600600001e6d9de6a
00000000e1d009000000000010111213
1415161718191a1b1c1d1e1f20212223
2425262728292a2b2c2d2e2f30313233
34353637
```

<details>
<summary>点这里看答案</summary>

**包 B：Port Unreachable**

- 外层 Source = `08 08 08 08` = 8.8.8.8，说明是目标发的；
- ICMP Type = `03`，Code = `03`，表示端口不可达；
- 内层 IPv4 Destination = 8.8.8.8；
- 内层 UDP Destination Port = 33434；
- `len(buf)` = 56，没有 payload。

结论：目标已经收到探测，但没有程序监听 33434，所以回了 Port Unreachable。**这就是“到了”的信号。**

**包 C：Echo Reply**

- 外层 Source = 8.8.8.8；
- ICMP Type = `00`, Code = `00`，是 Echo Reply（ping 的回复），不是错误；
- 没有内层 IPv4/UDP；
- `len(buf)` = 84。

结论：这个包和 traceroute 无关，应该忽略。它可能是你（或别人）跑 `ping` 留下的延迟包。

</details>

## 3.9 常见误区

| 误区 | 纠正 |
|---|---|
| 把 hex 当十进制 | `0x38` 是 56，不是 38 |
| 认为 `recvfrom` 的 `buf` 含以太网头 | Linux raw ICMP socket 从 IPv4 头开始 |
| 把内层 IPv4 当成外层 | 外层在前 20 字节；内层在 ICMP 头之后 |
| 认为 ICMP 头总是 8 字节，后面就是负载 | ICMP 错误包的负载是“内层 IP + UDP 头 + 可能的数据” |
| 用内层 Source 判断是不是自己的包 | 沙箱 NAT 会改写；用内层 Destination + UDP 端口 |
| 认为 `len(buf)` 一定等于内层 `total length` | 外层通常相等；内层可能只带了 8 字节 UDP，没有 payload |
| 忽略 IP options | `IHL > 5` 时头长大于 20，后面所有偏移都要后移 |
| 以为所有路由器都返回一样长的包 | 真实沙箱里 56、61 字节都出现过 |
