# 第 4 章 IPv4 / UDP / ICMP 与手动解码

这一章把 IPv4、UDP、ICMP 的头部逐字段讲清楚，然后手工解码三个真实回包。

## 本章目标

学完这一章，你应该能：

1. 不查表，写出 IPv4 头前 20 字节的字段顺序；
2. 解释 `IHL`、`total length`、`header_len` 的关系；
3. 写出 UDP 头 8 字节和 ICMP 头 8 字节的字段；
4. 手工解码一个真实的 Time Exceeded 包和 Port Unreachable 包；
5. 判断一个回包“是不是给我的”“是不是我发的探测”“是不是到了终点”。

这一章不写代码。下一章才把手工解码变成 Python。

> 本章所有包都来自 2026-10-26 的真实沙箱：沙箱 `169.254.68.6/30`，目标 `8.8.8.8`。外层字段随每次运行变化（IP ID、校验和），内层 UDP 源端口也会变，但解析方法不变。

## 4.1 IPv4 头：20 字节的“信封”

IPv4 头的最小长度是 20 字节。如果带了 options，会更长。

| 字段 | 位数 | 字节偏移 | 含义 | 本实验是否关心 |
|---|---|---|---|---|
| Version | 4 | 0 的高 4 位 | IP 版本，IPv4 = 4 | 是 |
| IHL | 4 | 0 的低 4 位 | 头部长度，单位是 4 字节 | 是 |
| Type of Service (TOS) | 8 | 1 | 优先级/DSCP/ECN | 否（真实包可能是 `0xb8`） |
| Total Length | 16 | 2–3 | 整个 IP 包的长度（头 + 负载），字节 | 是 |
| Identification | 16 | 4–5 | 分片标识 | 否 |
| Flags | 3 | 6 的高 3 位 | 分片标志 | 否 |
| Fragment Offset | 13 | 6 的低 5 位 + 7 | 分片偏移 | 否 |
| TTL | 8 | 8 | 还能走几跳 | 是 |
| Protocol | 8 | 9 | 上层协议：1=ICMP，17=UDP | 是 |
| Header Checksum | 16 | 10–11 | 头部校验和 | 否（不校验） |
| Source Address | 32 | 12–15 | 源 IP | 是 |
| Destination Address | 32 | 16–19 | 目标 IP | 是 |
| Options | 可变 | 20 起 | 可选字段 | 知道它可能存在即可 |

### 字节 0：Version 和 IHL 挤在一个字节里

```text
bit:   7 6 5 4   3 2 1 0
      +---------+---------+
      | Version |   IHL   |
      +---------+---------+
```

- `Version` = 高 4 位；
- `IHL` = 低 4 位，单位是 **4 字节**。

真实包 A 的字节 0 是 `0x45`：

```text
0x45 = 0100 0101
       ^^^^ ^^^^
       4    5
```

- Version = 4；
- IHL = 5 → 头长 = 5 × 4 = **20 字节**。

如果 IHL = 6，头长就是 24 字节，多出来的 4 字节是 options。后面所有偏移都要加 4。

### 字节 6–7：Flags 和 Fragment Offset

```text
byte 6:  +-----+-------------------+
         |Flags| Fragment Offset   |
         |3 bit| 高 5 位            |
         +-----+-------------------+
byte 7:  +--------------------------+
         | Fragment Offset 低 8 位   |
         +--------------------------+
```

- Flags = `byte6 >> 5`；
- Fragment Offset = `((byte6 & 0x1F) << 8) | byte7`。

真实包 A 的字节 6–7 是 `40 00`：

- `0x40 >> 5 = 2`，即 DF（Don't Fragment）位；
- Frag Offset = `((0x40 & 0x1F) << 8) | 0x00 = 0`。

本实验不处理分片，但解析类里要填这两个字段，所以要知道怎么取。

### Total Length

`Total Length` 是**整个 IP 包**的长度，包括 IP 头、UDP/ICMP 头和负载。单位是字节。

真实包 A：

- 外层 `Total Length` = `0x0038` = 56；
- `len(buf)` = 56；
- 两者相等。

但**内层** IP 头可能不一样：

- 内层 `Total Length` = `0x0021` = 33（20 IP + 8 UDP + 5 字节 `hello`）；
- ICMP 实际只带了 20 + 8 = 28 字节，没有 `hello`；
- 所以内层的 `Total Length` 比实际携带的字节数大 5。

这是正常的：ICMP 错误包只要求带原始数据**至少前 8 字节**，路由器可以少带后面的 payload。解析时只读你需要的 UDP 头，不要硬读缺失的 payload。

### Protocol

| 值 | 协议 |
|---|---|
| 1 | ICMP |
| 17 | UDP |

外层 IPv4 的 Protocol 是 1（ICMP），因为路由器回的是 ICMP 错误包。内层 IPv4 的 Protocol 是 17（UDP），因为原始探测是 UDP。

## 4.2 UDP 头：8 字节的“门牌号”

UDP 头固定 8 字节：

| 字段 | 位数 | 字节偏移 | 含义 |
|---|---|---|---|
| Source Port | 16 | 0–1 | 发送方端口 |
| Destination Port | 16 | 2–3 | 接收方端口 |
| Length | 16 | 4–5 | UDP 头 + 负载，字节 |
| Checksum | 16 | 6–7 | 校验和（本实验不校验） |

在本实验里：

- 外层 UDP 头不存在（外层是 ICMP）；
- 内层 UDP 头是**原始探测包**的 UDP 头，由 ICMP 错误包带回来；
- 内层 UDP 的 `Destination Port` 就是你当时发送的目标端口（例如 33435）。

真实包 A 的内层 UDP：

- Source Port = `0xe5b9` = 58809（内核分配的源端口）；
- Destination Port = `0x829b` = 33435；
- Length = `0x000d` = 13（8 UDP + 5 负载，但 payload 没被带回来）；
- Checksum = `0x9973`。

> 注意：`UDP Length` 包括 8 字节 UDP 头。比如负载 5 字节，Length = 13。

---

## 4.3 ICMP 头：8 字节的“错误说明”

ICMP 头的前 8 字节是固定的：

| 字段 | 位数 | 字节偏移 | 含义 |
|---|---|---|---|
| Type | 8 | 0 | 错误类型 |
| Code | 8 | 1 | 错误代码 |
| Checksum | 16 | 2–3 | 校验和（本实验不校验） |
| Rest of Header | 32 | 4–7 | 因 Type/Code 而异；本实验的两种错误都是 0 |

本实验重点记两个组合：

| Type | Code | 名称 | 谁发的 | 含义 |
|---|---|---|---|---|
| 11 | 0 | Time Exceeded / TTL Expired | 中间路由器 | 包在我这里过期了 |
| 3 | 3 | Destination Unreachable / Port Unreachable | 目标主机（理想模型） | 到了，但端口没人监听 |

其他 Type/Code 一律忽略（比如 `0/0` Echo Reply、`8/0` Echo Request）。

### ICMP 的负载是什么

ICMP 错误包的负载不是普通数据，而是：

```text
原始 IPv4 头（通常 20 字节，可能带 options）
+ 原始数据至少前 8 字节（对 UDP 来说就是 UDP 头）
```

真实包 A 的内层部分只有 28 字节（20 + 8），没有 `hello`；另一台路由器（`203.22.178.22`）的包则带了完整的 33 字节（20 + 8 + 5）。

这就是第 3 章看到的“内层 IPv4 + 内层 UDP”。

为什么至少带前 8 字节？因为 ICMP 只需要让发送方知道“是哪个包出错了”，而 UDP 头的前 8 字节（源端口、目标端口、长度、校验和）已经足够定位。多带多少由路由器决定。

## 4.4 手动解码：一个真实的 Time Exceeded 包

用第 3 章的包 A（真实 TTL=6 抓包）：

```text
45b80038fc804000f9015e5365e2d251
a9fe44060b00735d0000000045000021
fc8040000111ac30c0a8006308080808
e5b9829b000d9973
```

### 第 1 步：外层 IPv4

| 字段 | 字节 | 计算 | 结果 |
|---|---|---|---|
| Version | `45` 的高 4 位 | `0x45 >> 4` | 4 |
| IHL | `45` 的低 4 位 | `0x45 & 0x0F` | 5 |
| 头长 | IHL × 4 | 5 × 4 | 20 字节 |
| Total Length | `00 38` | `0x0038` | 56 |
| TTL | `f9` | `0xf9` | 249 |
| Protocol | `01` | `0x01` | 1 = ICMP |
| Source | `65 e2 d2 51` | 101.226.210.81 | 路由器 |
| Destination | `a9 fe 44 06` | 169.254.68.6 | 你的沙箱 |

结论：这个包是 `101.226.210.81` 发给 `169.254.68.6` 的 ICMP 包，总长 56 字节。

### 第 2 步：ICMP 头（偏移 20）

| 字段 | 字节 | 值 | 含义 |
|---|---|---|---|
| Type | `0b` | 11 | Time Exceeded |
| Code | `00` | 0 | TTL expired |
| Checksum | `73 5d` | 0x735d | 不校验 |
| Rest | `00 00 00 00` | 0 | — |

结论：这是一条“TTL 过期”的错误消息。

### 第 3 步：内层 IPv4（偏移 28）

| 字段 | 字节 | 计算 | 结果 |
|---|---|---|---|
| Version/IHL | `45` | — | IPv4，20 字节头 |
| Total Length | `00 21` | 0x0021 | 33 |
| Identification | `fc 80` | 0xfc80 | 64640 |
| Flags | `40` 的高 3 位 | 0x40 >> 5 | 2（DF） |
| TTL | `01` | 0x01 | 1 |
| Protocol | `11` | 0x11 | 17 = UDP |
| Source | `c0 a8 00 63` | — | 192.168.0.99（NAT 改写） |
| Destination | `08 08 08 08` | — | 8.8.8.8（目标） |

结论：触发错误的是“你发给 8.8.8.8 的 UDP 包”。内层源 IP 被沙箱 NAT 改写成了 `192.168.0.99`，不是你的沙箱 IP。

> 内层 TTL 是 1，因为探测包到达这台路由器时只剩 1 跳。真实设备有时显示 0 或 1，取决于复制 IP 头的时机；本实验不依赖这个字段。

### 第 4 步：内层 UDP（偏移 48）

| 字段 | 字节 | 值 | 含义 |
|---|---|---|---|
| Source Port | `e5 b9` | 0xe5b9 = 58809 | 内核分配的源端口 |
| Destination Port | `82 9b` | 0x829b = 33435 | 你发的目标端口 |
| Length | `00 0d` | 13 | 8 头 + 5 负载 |
| Checksum | `99 73` | 0x9973 | 不校验 |

### 第 5 步：负载

没有负载。虽然 UDP Length 说 13（8 + 5），但 ICMP 只带回了 UDP 头 8 字节；`hello` 没被带回来。

### 最终结论

```text
路由器 101.226.210.81 告诉你：
你发给 8.8.8.8:33435 的探测包，在我这里 TTL 过期了。
```

## 4.5 手动解码：一个真实的 Port Unreachable 包

用第 3 章的包 B（真实 TTL=15 抓包）：

```text
45b8003800000000fa01c1f808080808
a9fe44060303e8230000000045000021
8f374000011118fac0a8006308080808
99f8829a000de535
```

### 外层 IPv4

| 字段 | 字节 | 值 | 含义 |
|---|---|---|---|
| Total Length | `00 38` | 56 | — |
| Identification | `00 00` | 0 | — |
| Flags | `00` 的高 3 位 | 0 | — |
| TTL | `fa` | 250 | — |
| Protocol | `01` | 1 | ICMP |
| Source | `08 08 08 08` | 8.8.8.8 | 目标主机 |
| Destination | `a9 fe 44 06` | 169.254.68.6 | 你 |

### ICMP 头

| 字段 | 字节 | 值 | 含义 |
|---|---|---|---|
| Type | `03` | 3 | Destination Unreachable |
| Code | `03` | 3 | Port Unreachable |
| Checksum | `e8 23` | 0xe823 | 不校验 |

结论：目标主机 8.8.8.8 告诉你“这个端口没人监听”。

### 内层 IPv4

| 字段 | 字节 | 值 | 含义 |
|---|---|---|---|
| Total Length | `00 21` | 33 | 原始探测包总长 |
| Identification | `8f 37` | 36663 | — |
| Flags | `40` 的高 3 位 | 2（DF） | — |
| TTL | `01` | 1 | 探测到达目标时只剩 1 跳 |
| Protocol | `11` | 17 | UDP |
| Source | `c0 a8 00 63` | 192.168.0.99 | NAT 改写后的源 |
| Destination | `08 08 08 08` | 8.8.8.8 | 目标 |

### 内层 UDP

| 字段 | 字节 | 值 | 含义 |
|---|---|---|---|
| Source Port | `99 f8` | 39416 | 内核分配的源端口 |
| Destination Port | `82 9a` | 33434 | 你发的目标端口 |
| Length | `00 0d` | 13 | 8 头 + 5 负载 |
| Checksum | `e5 35` | 0xe535 | 不校验 |

### 最终结论

```text
目标 8.8.8.8 告诉你：
你发给我的 33434 端口没有程序监听，所以我回 Port Unreachable。
```

这就是 traceroute 判断“到了”的信号。

> 注意：这个 Port Unreachable 的内层 TTL 也是 1。真实设备复制 IP 头时可能已经递减过 TTL；这个字段对本实验不重要，不要拿它做判断。

## 4.6 三个判断

拿到一个回包，不要急着解析所有字段。先做三个判断：

### 判断 1：是不是给我的？

看外层 IPv4 的 Destination。它应该是你的沙箱地址（本环境是 `169.254.68.6`）。

但在实际代码里，raw socket 只会收到发给你的包，所以这个判断通常可以跳过。

### 判断 2：是不是我发的探测？

看内层 IPv4 的 Protocol 和 Destination，再看内层 UDP 的 Destination Port：

- 内层 Protocol 应该是 17（UDP）；
- 内层 Destination 应该是你的目标 `ip`；
- 内层 UDP Destination Port 应该是你发送时用的端口（例如 33435）。

如果对不上，说明这个包可能是同一台机器上其他程序的、上一个程序的、或者延迟很久的，应该忽略。

> 不要用内层 Source 判断。沙箱 NAT 会把它改写成 `192.168.0.99` 一类地址。

### 判断 3：是不是到了终点？

最简单的判断：**外层 Source == 目标 `ip`**。

在本实验的理想模型里，Port Unreachable 由目标主机回，所以外层 Source 就是目标。真实包 B 的外层 Source 正是 `8.8.8.8`。不过 NAT/防火墙也可能发 `3/3`，源不一定是目标；更稳的判断见下一段。

更严谨的判断：ICMP Type=3 且 Code=3，并确认内层 Destination 是目标、内层 UDP 目的端口是本次探测用的端口。本实验不强制做到这一步；第 8 章会讲完整判断和它的已知风险。

## 4.9 常见误区

| 误区 | 纠正 |
|---|---|
| `total length` 是负载长度 | 是整个 IP 包（头 + 负载） |
| `IHL` 就是字节数 | IHL 的单位是 4 字节，头长 = IHL × 4 |
| `flags` 占 4 位 | Flags 占 3 位，Fragment Offset 占 13 位 |
| ICMP Type 和 Code 是一回事 | Type 是大类，Code 是细分；`3/3` 才是端口不可达 |
| ICMP 头后面直接是负载 | 错误包的负载先是内层 IPv4 头，再是 UDP 头 |
| 内层 `total length` 一定等于实际字节数 | 真实包 A 的内层 total 是 33，但实际只有 28（没带 payload） |
| 内层 Source 就是自己的 IP | 沙箱 NAT 会改写成 `192.168.0.99`，不要用它判断 |
| `header_len` 和 `length` 是一回事 | `header_len` 是 IP 头长；`length` 是整个包长 |
| TOS 一定是 0 | 真实包 A/B/C 的 TOS 是 `0xb8`，本实验忽略 |
| 所有 IP 头都是 20 字节 | 有 options 时更长；用 `header_len` 动态算 |
